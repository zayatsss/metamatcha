# MetaMatcha — Multi-Account Trading Dashboard

Дашборд для одновременного управления несколькими торговыми аккаунтами на
**MetaTrader 5** и **MatchTrader**: расчёт лота по индивидуальному риску каждого
счёта, исполнение ордеров в один клик на всех аккаунтах и автоматическое
сопровождение сделок по ценовым триггерам.

> Статус: рабочий каркас backend (FastAPI) + ключевая доменная логика + пример
> компонента frontend. Адаптеры брокеров реализованы по реальному контракту, но
> требуют боевых креденшелов/терминала для интеграционного запуска.

---

## 1. Технический стек

| Слой        | Выбор                              | Почему |
|-------------|------------------------------------|--------|
| Backend     | **Python + FastAPI** (async)       | MT5-библиотека только под Python; async идеально для параллельных вызовов на N аккаунтов и фонового воркера |
| Frontend    | **React + TypeScript** (Next.js или Electron-renderer) | Для десктоп-приложения трейдера логичнее **Electron** (системный трей, локальный запуск рядом с терминалами MT5) |
| БД          | **SQLite** на старте → **PostgreSQL** в проде | SQLite хватает для одного пользователя; Postgres — при мультипользовательском/облачном деплое |
| Транспорт   | REST + **WebSocket** (стрим статусов/цен в UI) | |

## 2. Архитектура

```
┌──────────────────────────────────────────────┐
│  Frontend (React/Electron)                     │
│  • Account Management   • Order Panel          │
│  • Trade Management (триггеры)                 │
└───────────────┬───────────────┬────────────────┘
        REST (CRUD/execute)   WebSocket (статусы, цены, события триггеров)
                │               │
┌───────────────▼───────────────▼────────────────┐
│  Backend (FastAPI, один процесс/хост)           │
│                                                 │
│  routers/  accounts · orders · triggers         │
│  services/ execution (расчёт лота + рассылка)   │
│  risk.py   формула лотности                     │
│  workers/  TriggerMonitor (asyncio background)  │
│  brokers/  BrokerManager → BrokerAdapter        │
│            ├── MT5Adapter (sync→to_thread)      │
│            └── MatchTraderAdapter (httpx async) │
│  models/   SQLAlchemy (Account/TradeGroup/Trigger)
└───────┬─────────────────────────────┬───────────┘
        │                             │
┌───────▼────────┐            ┌────────▼─────────┐
│  MT5 terminal  │            │ MatchTrader API   │
│ (Windows host) │            │  (REST + WS)      │
└────────────────┘            └───────────────────┘
```

**Ключевая абстракция** — `BrokerAdapter` (`app/brokers/base.py`). Вся
бизнес-логика (исполнение, сопровождение) работает только с этим интерфейсом и
не знает про специфику MT5/MatchTrader. Добавить нового брокера = реализовать
один класс.

**Важно про MT5:** библиотека `MetaTrader5` синхронная, работает только на
Windows и держит один логин на инстанс терминала. Поэтому:
- вызовы MT5 заворачиваются в `asyncio.to_thread`;
- на каждый MT5-аккаунт — отдельный терминал/инстанс (в проде — отдельный
  процесс-коннектор на Windows-хосте, общающийся с backend по сети).
MatchTrader — обычный HTTP/WS API, работает кроссплатформенно через `httpx`.

## 3. Модули

### 3.1 Account Management (`routers/accounts.py`, `models.py`)
CRUD аккаунтов (MT5 / MatchTrader), поля: логин/пароль (хранится зашифрованным,
`security.py`), сервер, баланс, **risk_percent**. Эндпоинты connect/disconnect
поднимают/гасят подключение через `BrokerManager`; статус Коннект/Дисконнект
отдаётся в `GET /accounts`.

### 3.2 Order Execution & Lot Calculator (`risk.py`, `services/execution.py`, `routers/orders.py`)
Формула (`risk.py`):
```
risk_amount = balance * risk% / 100
lot         = risk_amount / (SL_в_пунктах * стоимость_пункта_на_лот)
```
Стоимость пункта **не зашита константой** — берётся из спецификации символа у
брокера (`get_symbol_spec`), потому что зависит от инструмента и валюты счёта.
Лот округляется **вниз** под `volume_step` и клампится в `[volume_min, volume_max]`.
`POST /orders/execute` параллельно (`asyncio.gather`) считает лот и шлёт ордер на
каждый выбранный аккаунт, возвращая по каждому результат (лот, фактический риск,
тикет/ошибку).

### 3.3 Trade Management & Triggers (`models.Trigger`, `workers/trigger_monitor.py`)
Три действия по достижении целевой цены:
- **BREAK_EVEN** — перенос SL на цену входа;
- **PARTIAL_TP** — закрытие N % текущего объёма;
- **CUSTOM_SL_MOVE** — перенос SL на заданную цену.
`account_id=None` => действие применяется ко всем активным аккаунтам.

## 4. Фоновый воркер (логика сопровождения)

`TriggerMonitor` (`app/workers/trigger_monitor.py`) — `asyncio.Task`, который
стартует в `lifespan` приложения. Каждые `trigger_poll_interval` секунд:

1. читает из БД взведённые триггеры (`is_armed && !is_fired`);
2. группирует по символу и тянет текущую цену **один раз на символ**;
3. ловит **пересечение** уровня: сравнивает прошлую и текущую цену — сработка,
   когда `target` оказался между ними (надёжнее, чем `price >= target`, не
   зависит от стороны подхода);
4. при сработке параллельно применяет действие на нужных аккаунтах и ставит
   `is_fired=True` в БД (источник правды → перезапуск не задвоит действие).

Для боевого режима цену лучше питать из **WS-стрима** брокера (push), а не
поллингом — структура `_fetch_prices`/`_last_price` к этому готова.

## Запуск (backend)

```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload      # http://localhost:8000/docs
pytest                              # юнит-тесты расчёта лота
```

`MetaTrader5` устанавливается отдельно и только на Windows-хосте с терминалом
(строка закомментирована в `requirements.txt`).
